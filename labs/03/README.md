## Мақсаты

Құжаттар тізіліміне HTTP арқылы қол жеткізу. Swagger UI-де серверді іске қосуды, жазбаларды оқуды және қосуды, кіріс деректерін тексеруді және дерекқор сессиясын басқаруды көрсету.

## Сервердің құрылымы

[`app/main.py`](../../app/main.py) FastAPI қолданбасын құрады, іске қосылған кезде кестелерді дайындап, маршруттар тобын тіркейді. Маршруттар [`app/routers/documents.py`](../../app/routers/documents.py) файлында орналасқан. `Depends(get_session)` тәуелділігі әр сұрау кезінде SQLModel сессиясын ашады. Контекст менеджері аяқталғанда сессия жабылады. [`DocumentCreate` және `DocumentRead`](../../app/database/models.py) сұрауда қабылданатын және жауапта қайтарылатын өрістерді анықтайды. Идентификаторды, тіркеу нөмірін және тіркеу күнін сервер белгілейді.

| Әдіс пен жол | Нәтиже |
| --- | --- |
| `GET /` | `200`. API туралы қысқаша мәлімет пен құжаттама сілтемесі. |
| `GET /health` | `200`. Сервердің жұмыс істеп тұрғанын растайды. |
| `GET /documents` | `200`. Құжат карточкалары бар JSON массиві. |
| `GET /documents/{document_id}` | Карточка табылса `200`, көрсетілген идентификаторға жазба табылмаса `404`. |
| `GET /documents/lookups` | `200`. Формаларға арналған құжат түрлері, мәртебелер және бөлімдер. |
| `POST /documents` | Жаңа карточка жасалса `201`, деректер жарамсыз болса `422`. |

## Көрсету реті

Виртуалды ортаны белсендіріп, алдымен бастапқы деректерді енгізіңіз, содан кейін Uvicorn серверін іске қосыңыз. Командаларды жоба түбірінде орындаңыз.

```bash
python -m app.database.seed
python -m uvicorn app.main:app --reload
```

[Swagger UI](http://127.0.0.1:8000/docs) бетін ашыңыз. Әр қадамда тиісті маршрутты таңдап, **Try it out** және **Execute** батырмаларын басыңыз.

1. `GET /documents` сұрауын орындап, жауаптан `document_id` мәнін алыңыз. Сол идентификатормен `GET /documents/{document_id}` сұрауын орындаңыз.
2. Қолдағы түрлер мен мәртебелерді `GET /documents/lookups` арқылы тексеріңіз. Жаңа дерекқор үшін төмендегі мысалды қолдануға болады. Егер дерекқорды қолмен толтырған болсаңыз, анықтамалықтағы идентификаторларды қойыңыз. `POST /documents` сұрауын орындап, `201` жауабындағы `document_id` мәнін жазып алыңыз.
3. `POST` сұрауын `"title": "А"` мәнімен қайталаңыз. Тақырып кемінде үш таңбадан тұруы керек, сондықтан сервер `422` қайтарады.
4. Жоқ идентификатормен `GET /documents/{document_id}` сұрауын орындаңыз. Сервер `404` қайтарады.

### POST сұрауының денесіне мысал

```json
{
  "title": "Анықтама беру туралы өтініш",
  "description": "Қорғауға арналған оқу карточкасы",
  "document_type_id": 1,
  "status_id": 1,
  "created_by_user_id": 1,
  "direction": "Ішкі",
  "priority": "Қалыпты"
}
```

## Бақылау сұрақтары

1. **REST API дегеніміз не және GET пен POST қалай қолданылады?** REST API-де ресурстар адрес арқылы қолжетімді. `GET /documents` тізілімді оқиды. `POST /documents` жаңа карточка құруға арналған деректерді жіберіп, жүйенің күйін өзгертеді.
2. **Pydantic не үшін керек?** Ол JSON-ды оқып, өрістердің түрін, міндеттілігін, ұзындығын және рұқсат етілген мәндерін тексереді. Мысалы, тым қысқа тақырып жазба дерекқорға сақталмай тұрып кері қайтарылады.
3. **`Depends(get_session)` не береді?** FastAPI тәуелділіктің қашан ашылып, қашан жабылатынын басқарады және тест кезінде оны алмастыра алады. Жеке сессиялар сұраулар қатар орындалғанда олардың транзакцияларын оқшаулайды.
4. **Swagger UI қалай жасалады?** FastAPI маршруттардың сипаттамасынан, параметр түрлерінен және модельдерден OpenAPI спецификациясын құрады. Swagger UI осы спецификацияны пайдаланады және `/docs` адресінде ашылады.
5. **`422` нені білдіреді?** Сервер сұрауды қабылдады, бірақ деректер белгіленген талаптарға сәйкес келмейді. Мысалы, тақырып үш таңбадан қысқа, күн пішімі қате немесе таңдалған құжат түрі анықтамалықта жоқ.
