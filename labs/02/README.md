## Мақсаты

«Деканаттың» ER сызбасын реляциялық дерекқорға көшіру, кесте байланыстарын SQLModel арқылы сипаттау және SQLite дерекқорын оқу деректерімен толтыру.

## Іске асыру

| Файл | Қорғауда нені көрсету керек |
| --- | --- |
| [`app/database/models.py`](../../app/database/models.py) | Кесте модельдері, бастапқы және сыртқы кілттер, бірегейлік шектеулері және `Relationship` арқылы берілген объектілік байланыстар. |
| [`app/database/db.py`](../../app/database/db.py) | Дерекқор қозғалтқышы, `SQLModel.metadata.create_all()` арқылы кесте құру және SQLite-та сыртқы кілттерді тексеруді қосу. |
| [`app/database/seed.py`](../../app/database/seed.py) | Дерекқор құру, анықтамалықтарды, пайдаланушыларды, құжаттар мен оларға қатысты үлгі жазбаларды енгізу. |

`DeanDocument` құжат моделінің бастапқы кілті — `document_id`. `document_type_id` өрісі `document_types.document_type_id` бағанына сілтейді, ал `document_type` Python кодында байланысты объектіні алуға мүмкіндік береді. Құжаттың мәртебесі, авторы және бөлімі де осы тәсілмен байланысқан. Тіркеу нөмірі бірегей.

Құжаттар мен орындаушылар арасындағы «көптен көпке» байланысы `ExecutorAssignment` арқылы берілген. Тағайындауда құжатқа, орындаушыға және тапсырма берген қызметкерге сілтемелер болады. Онда тапсырманың сипаттамасы мен орындалу мерзімін де сақтауға болады. Келісулер, өзгерістер тарихы, түсініктемелер және тіркемелер құжатпен «бірден көпке» қатынасы арқылы байланысады.

## Тексеру

Виртуалды ортаны белсендіріп, жоба түбірінен бастапқы деректерді енгізетін команданы екі рет орындаңыз. Содан кейін дерекқор файлын елемеу ережесін тексеріңіз.

```bash
python -m app.database.seed
python -m app.database.seed
git check-ignore -v -- deanflow_labs.db
```

`DATABASE_URL` әдепкі мәнінде бағдарлама жоба түбірінде `deanflow_labs.db` файлын құрады. Қайта іске қосылғанда бар үлгі жазбаларды кілттері бойынша табады.

Дайын кестелерді және олардың байланыстарын тексеру үшін интерактивті Python ортасында мына кодты орындаңыз.

```python
import sqlite3

with sqlite3.connect("file:deanflow_labs.db?mode=ro", uri=True) as db:
    tables = db.execute(
        "SELECT name FROM sqlite_master WHERE type = 'table' ORDER BY name"
    ).fetchall()
    print([name for (name,) in tables])
    print(db.execute("SELECT COUNT(*) FROM documents").fetchone()[0])
    print(db.execute("SELECT COUNT(*) FROM document_approvals").fetchone()[0])
    print(db.execute("PRAGMA foreign_key_list(documents)").fetchall())
    print(db.execute("PRAGMA foreign_key_check").fetchall())
```

Құжат айналымының оқу сызбасында 11 кесте бар. Бастапқы деректер енгізілгенде әр кестеге үш немесе төрт үлгі жазба қосылады. Мысалы, тізілімде төрт құжат карточкасы, келісулер кестесінде үш жазба пайда болады. Соңғы нұсқада есептік деректер мен пайдаланушы сеанстарына арналған екі қосымша кесте бар. Кестелер арасындағы сілтемелер дұрыс болса, соңғы команда `[]` шығарады.

### ORM модельдерін ЖИ көмекшісімен тексеруге арналған сұрау үлгісі

> DeanFlow ORM модельдерін оның ER диаграммасымен салыстыр. `DeanDocument` моделінің бастапқы кілтін, анықтамалықтармен байланысын және міндетті өрістерін тексер. `ExecutorAssignment` моделінде орындаушы мен оны тағайындаған қызметкерге бөлек сыртқы кілттер қолданылғанын тексер. Осы байланыстарды қандай SQLite сұрауларымен растауға болатынын түсіндір.

## Бақылау сұрақтары

1. **ORM дегеніміз не?** Object-Relational Mapping — Python кластары мен реляциялық кестелерді сәйкестендіру тәсілі. SQLModel және SQLAlchemy объектілерді оқу және сақтау үшін SQL сұрауларын құрады, өзгерістерді сессия аясында басқарады.
2. **Сыртқы кілт пен `Relationship` қандай қызмет атқарады?** `document_type_id` — анықтамалықтағы жолдың идентификаторы сақталатын баған. `document_type` — құжат түрінің Python объектісін алуға арналған ORM атрибуты. Бұл атрибут үшін кестеде бөлек баған құрылмайды.
3. **Бастапқы деректерді енгізу не үшін қажет?** Алдын ала дайындалған құжаттар мен анықтамалықтар тізімді, сүзгілерді және формаларды бірден тексеруге мүмкіндік береді. Мысалы, іздеу үшін кемінде бір құжат, ал жаңа карточка қосу үшін таңдайтын құжат түрі қажет.
4. **`echo=True` не береді?** SQLAlchemy орындалған SQL операторлары мен олардың параметрлерін журналға шығарады. Бұл кестелердің құрылуын, сұраулардың ретін және транзакциялардың бекітілуін көруге мүмкіндік береді. Зертханалық жұмыста журналдауды оқу деректерімен қолдануға болады.
5. **Git-те неге модель сақталады, ал дерекқор файлы еленбейді?** Модельді пайдаланып бірдей сызбаны қайта құруға және оның өзгерістерін `git diff` командасымен қарауға болады. SQLite файлы жергілікті дерекқордың ағымдағы күйін және өзгертілген деректерді сақтайды.
