# Лабораторная работа № 6. Контейнеризация с Docker Compose

**Цель** — запустить FastAPI и Streamlit в отдельных контейнерах, связать их по сети Compose и сохранить SQLite между перезапусками.

## Реализация

| Компонент | Настройка |
| --- | --- |
| `backend` | Образ `python:3.11-slim`, заполнение SQLite демонстрационными данными при старте, Uvicorn на порту `8000`, проверка готовности через `GET /health`. |
| `frontend` | Образ `python:3.11-slim`, Streamlit на порту `8501`, ожидание готовности API и `BACKEND_URL=http://backend:8000`. |
| Хранилище | Именованный том `deanflow-demo-data` смонтирован в `/data`. API использует `/data/deanflow-labs.db`. |
| Контекст сборки | `.dockerignore` исключает виртуальные окружения, кэш, локальные базы и другие файлы среды разработки. |

[Конфигурация Compose](../../docker-compose.yml) · [Dockerfile API](../../Dockerfile) · [Dockerfile Streamlit](../../Dockerfile.frontend) · [Исключения сборки](../../.dockerignore)

## Запуск и показ преподавателю

Из корня репозитория, с запущенным Docker и свободными портами `8000` и `8501`, выполните команды.

```bash
docker compose config --quiet
docker compose up --build -d
docker compose ps
docker compose logs --tail 40 backend frontend
```

Compose публикует оба сервиса на `127.0.0.1`. Если порты заняты, задайте переменные `DEANFLOW_API_PORT` и `DEANFLOW_UI_PORT` перед запуском и используйте выбранные порты в браузере.

1. В выводе `docker compose ps` покажите оба сервиса и статус готовности `backend`. Откройте `/health` и Swagger UI. [Проверка API](http://localhost:8000/health) · [Swagger UI](http://localhost:8000/docs)
2. В Streamlit найдите демонстрационный документ и создайте отдельный документ `Проверка тома ЛР 06`. Запишите номер. [Интерфейс](http://localhost:8501)
3. Выполните `docker compose down`, затем `docker compose up -d`. После запуска найдите документ по тому же номеру и удалите учебную запись через интерфейс.

## Контрольные вопросы

- **Чем контейнер отличается от виртуальной машины?** Контейнер изолирует процесс, его файловую систему и сеть и использует ядро хоста. Виртуальная машина запускает собственную гостевую ОС и ядро.
- **Для чего нужны инструкции Dockerfile?** `WORKDIR` задаёт рабочий каталог, `COPY` переносит файлы в образ, `EXPOSE` документирует порт, `RUN` выполняет команду при сборке, `CMD` задаёт команду по умолчанию при запуске контейнера. Публикация порта выполняется настройкой `ports` в Compose.
- **Зачем нужен `.dockerignore`?** Он уменьшает контекст сборки и исключает локальные файлы окружения. Если скопировать `venv`, в образ попадут лишние зависимости и пути или бинарные файлы, привязанные к системе разработчика.
- **Как работает адрес `http://backend:8000`?** Встроенный DNS Docker в сети Compose разрешает имя сервиса `backend` в адрес его контейнера. Хост использует проброшенный порт, поэтому Swagger доступен по `localhost:8000`.
- **Что произойдёт с SQLite после `docker compose down`?** Файл базы сохранится в именованном томе. Если выполнить `down -v`, Compose удалит и том.
