# № 4 зертханалық жұмыс. CRUD, ішінара жаңарту және іздеу

[Жобаға оралу](../../README.md) · [№ 3 зертханалық жұмыс](../03/README.md) · [№ 5 зертханалық жұмыс](../05/README.md)

**Касанова Аружан · ИС-24А**

## Мақсаты

Құжатпен жұмыс істеудің толық циклін орындау. Қорғауда карточка жасап, оны сүзгілер арқылы табыңыз, таңдалған өрістерді өзгертіп, соңында жазбаны жойыңыз.

## Іске асыру

| Операция | Маршрут | Кодтың әрекеті |
| --- | --- | --- |
| Create — құру | `POST /documents` | Кіріс өрістері мен анықтамалық мәндерді тексереді, құжат жасап, `201` қайтарады. |
| Read — оқу | `GET /documents`, `GET /documents/{document_id}` | Құжаттарды дерекқордан оқиды. Көрсетілген идентификаторға жазба табылмаса, `404` қайтарады. |
| Update — жаңарту | `PATCH /documents/{document_id}` | `model_dump(exclude_unset=True)` арқылы тек жіберілген өрістерді алады, өзгерістерді тексеріп, `sqlmodel_update()` әдісін шақырады. Жаңартылған карточканы қайтарады. |
| Delete — жою | `DELETE /documents/{document_id}` | Карточканың бар-жоғын тексереді, оны тәуелді жазбаларымен бірге жойып, `204` қайтарады. |

Операциялар [`app/routers/documents.py`](../../app/routers/documents.py) файлында, ал жаңарту сұрауының `DocumentUpdate` схемасы [`app/database/models.py`](../../app/database/models.py) файлында орналасқан.

Тізімнің `search`, `status_code` және `direction` параметрлерін бірге пайдалануға болады. Іздеу құжат тақырыбы мен тіркеу нөмірі бойынша жүргізіледі. Әдепкіде белсенді карточкалар көрсетіледі. `include_archived=true` архивтегі карточкаларды да қосады. `limit` параметрі нәтиже санын 1 мен 200 аралығында шектейді. Сұрау шарттары SQLModel және SQLAlchemy өрнектерімен құрылады. Параметр мәндері дерекқор драйверіне SQL сұрауының құрылымынан бөлек беріледі.

## Swagger UI-де көрсету

Серверді [№ 3 зертханалық жұмыстың нұсқаулығы](../03/README.md) бойынша іске қосып, [Swagger UI](http://127.0.0.1:8000/docs) бетін ашыңыз.

1. `GET /documents` сұрауында `search=DF-DEMO-0001` және `status_code=IN_PROGRESS` мәндерін көрсетіңіз. Оқу деректерінде `DF-DEMO-0001` тіркеу нөмірі бар жазба қайтарылады.
2. № 3 жұмыстағы мысалмен `POST /documents` арқылы уақытша карточка жасаңыз. Жауаптағы `document_id` мәнін жазып алып, `PATCH /documents/{document_id}` сұрауының денесіне `{"title": "Анықтама беру туралы нақтыланған өтініш"}` енгізіңіз.
3. Осы карточканы `GET` арқылы оқып, нәтижені оны құру кезіндегі жауаппен салыстырыңыз. Тақырып жаңарады, ал тіркеу нөмірі, түрі мен мәртебесі бұрынғы мәндерінде қалады.
4. `PATCH` сұрауына `{"title": null}` денесін беріңіз. Міндетті тақырыпты тазалау әрекеті `422` қайтарады. `description` сияқты міндетті емес өрісті тазалау үшін `null` беруге болады.
5. Уақытша карточканы `DELETE` әдісімен жойыңыз. Сервер бос денесі бар `204` жауабын қайтарады. Сол идентификатормен қайталанған `GET` және `PATCH` сұраулары `404` қайтарады.

## Бақылау сұрақтары

1. **PUT пен PATCH қандай жағдайда қолданылады?** PUT ресурстың өңделетін өрістерін толық ауыстыруға арналған. PATCH таңдалған өрістерді ішінара жаңартады. Бір өрісті өзгерту үшін сол өрісті ғана жіберуге болады.
2. **Сұрау параметрлері дегеніміз не?** URL-де `?` белгісінен кейін жазылатын кілт пен мән жұптары. Параметрлер `&` белгісімен бөлінеді. Мысалы, `/documents?search=DF-DEMO-0001&status_code=IN_PROGRESS`.
3. **Жіберілмеген өрістер мен `null` мәні қалай өңделеді?** Схема кей өрістерді жібермеуге мүмкіндік береді. `exclude_unset=True` тек сұрауда берілген өрістерді қалдырады. Маршрут міндетті өрістер үшін `null` мәнін қабылдамайды. Міндетті емес өрісті `null` арқылы тазалауға болады.
4. **Жою алдында идентификаторды не үшін тексереміз?** Карточка табылмаса, API `404` қайтарады. Табылса, карточка мен оған тәуелді деректер бір транзакцияда өңделіп, жойылады.
5. **CRUD дегеніміз не?** Create — `POST` арқылы құру. Read — `GET` арқылы оқу. Update — `PATCH` немесе `PUT` арқылы жаңарту. Delete — `DELETE` арқылы жою.
