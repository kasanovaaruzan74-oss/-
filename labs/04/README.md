## Цель

Выполнить полный цикл работы с документом. На демонстрации создайте карточку, найдите её по фильтрам, измените выбранные поля и удалите запись.

## Реализация

| Операция | Маршрут | Что делает код |
| --- | --- | --- |
| Create | `POST /documents` | Проверяет входную схему и справочники, создаёт документ, возвращает `201`. |
| Read | `GET /documents`, `GET /documents/{document_id}` | Выбирает документы из базы. Если конкретного ID нет, возвращает `404`. |
| Update | `PATCH /documents/{document_id}` | Получает явно присланные поля через `model_dump(exclude_unset=True)`, проверяет изменения и вызывает `sqlmodel_update()`. Возвращает обновлённую карточку. |
| Delete | `DELETE /documents/{document_id}` | Проверяет наличие карточки и удаляет её вместе с зависимыми записями. Возвращает `204`. |

Код операций находится в [`app/routers/documents.py`](../../app/routers/documents.py), входная схема обновления `DocumentUpdate` — в [`app/database/models.py`](../../app/database/models.py).

Параметры списка `search`, `status_code` и `direction` работают совместно. Поиск применяется к заголовку и регистрационному номеру. По умолчанию в результат попадают активные карточки. Параметр `include_archived=true` включает архивные, а `limit` задаёт размер выборки в диапазоне от 1 до 200. Условия строятся выражениями SQLModel и SQLAlchemy, а значения параметров передаются драйверу отдельно от структуры SQL.

## Демонстрация в Swagger

Откройте [Swagger UI](http://127.0.0.1:8000/docs) после запуска [по инструкции № 3](../03/README.md).

1. В `GET /documents` укажите `search=DF-DEMO-0001` и `status_code=IN_PROGRESS`. На учебных данных ожидается запись с регистрационным номером `DF-DEMO-0001`.
2. Создайте временную карточку через `POST /documents` по примеру из № 3. Запишите выданный `document_id` и выполните `PATCH /documents/{document_id}` с телом `{"title": "Уточнённое заявление на выдачу справки"}`.
3. Выполните `GET` для этой карточки и сравните с ответом на создание. Заголовок должен обновиться, регистрационный номер, тип и статус сохраняются.
4. Выполните `PATCH` с телом `{"title": null}`. Ожидается `422`. Для поля, которое разрешено очищать, например `description`, явное значение `null` допустимо.
5. Выполните `DELETE` для временной карточки. Ожидается `204` с пустым телом. Повторные `GET` и `PATCH` с тем же ID должны вернуть `404`.

## Контрольные вопросы

1. **Чем отличаются PUT и PATCH?** PUT передаёт полное представление ресурса для замены. PATCH описывает частичное изменение, поэтому для правки одного поля достаточно короткого запроса.
2. **Что такое query-параметры?** Это пары ключей и значений после знака `?` в URL. Символ `&` разделяет параметры, например `/documents?search=DF-DEMO-0001&status_code=IN_PROGRESS`.
3. **Как обрабатываются пропущенные поля и `null`?** Схема допускает пропуск полей, а `exclude_unset=True` оставляет только переданные. Роутер отдельно отклоняет `null` для обязательных полей. В необязательных полях `null` позволяет очистить значение.
4. **Зачем проверять ID перед удалением?** Это даёт API возможность вернуть `404` для отсутствующей карточки и удалить найденные данные в одной транзакции с обработкой зависимостей.
5. **Что такое CRUD?** Create — `POST`, Read — `GET`, Update — `PATCH` или `PUT`, Delete — `DELETE`.
