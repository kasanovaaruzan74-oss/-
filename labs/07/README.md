# Лабораторная работа № 7. Автоматизированное тестирование и защита

**Цель** — проверить маршруты деканата автоматическими тестами и показать взаимодействие интерфейса, REST API и базы данных.

## Автоматические проверки

`pytest` запускает тесты через `FastAPI TestClient`. Фикстура подменяет зависимость получения сессии и создаёт отдельный файл SQLite во временном каталоге для каждого теста. Сценарии используют собственные справочники и учебную учётную запись. [Сценарии API](../../tests/test_documents_api.py) · [Тестовая фикстура](../../tests/conftest.py)

| Сценарий | Ожидаемый результат |
| --- | --- |
| Получение списка без документов | `GET /documents` отвечает `200` и возвращает пустой список. |
| Создание и повторное чтение | `POST` отвечает `201` и выдаёт регистрационный номер. Созданный документ читается по ID. |
| Невалидная тема | `POST` с темой из одного символа отвечает `422`. |
| Фильтр по статусу | Выдаются документы только с запрошенным статусом. |
| Неизвестный идентификатор | `GET`, `PATCH` и `DELETE` отвечают `404`. |
| Частичное обновление и удаление | `PATCH` меняет тему, сохраняя приоритет. `DELETE` отвечает `204`, после чего чтение отвечает `404`. |
| Поиск со специальными символами | API обрабатывает строку как значение фильтра и возвращает корректный список. |

Из корня репозитория в активном виртуальном окружении выполните команды.

```bash
python -m pip install -r requirements.txt
python -m pytest -q tests/test_documents_api.py
```

Для проверки качества кода покажите ограничения длины и типа данных в моделях SQLModel, ответ `404` при запросе отсутствующего объекта и условия поиска, которые строятся выражениями SQLAlchemy с привязкой параметров. [Модели](../../app/database/models.py) · [Маршруты](../../app/routers/documents.py)

## Контрольные вопросы

- **Зачем нужны автоматические тесты?** Они воспроизводимо проверяют API после каждого изменения. Ручной показ помогает оценить сценарий глазами пользователя, а тесты повторяют набор проверок статусов, содержимого ответа и изменений базы.
- **Что делает `TestClient`?** Он передаёт запросы приложению внутри тестового процесса. Для этих тестов отдельный процесс Uvicorn запускать не требуется.
- **Почему для тестового клиента нужна HTTP-библиотека?** Она помогает сформировать HTTP-запрос и получить структурированный ответ, чтобы проверить статус, заголовки и JSON. `httpx` также предоставляет асинхронный клиент для тестов с `async`/`await`.
- **Что даёт ИИ-ревью?** Оно помогает быстро предложить граничные случаи и найти места, где стоит проверить валидацию, обработку ошибок и работу с БД. Результаты подтверждаются чтением кода и воспроизводимыми тестами.
- **Что такое регрессионный тест?** Он фиксирует ожидаемое поведение. Например, при доработке `PATCH` тест проверит, что изменение темы по-прежнему сохраняет приоритет.
