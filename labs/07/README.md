# № 7 зертханалық жұмыс. Автоматтандырылған тестілеу және қорғау

**Мақсаты** — деканаттың API маршруттарын автоматтандырылған тестілермен тексеру және интерфейстің, REST API мен дерекқордың өзара жұмысын көрсету.

## Автоматтандырылған тексерулер

`pytest` тестілерді FastAPI-дің `TestClient` клиенті арқылы жүргізеді. Тест фикстурасы дерекқор сеансын алу тәуелділігін алмастырып, әр тест үшін уақытша бумада бөлек SQLite файлын жасайды. Сценарийлер сол дерекқордағы анықтамалықтар мен сынаққа арналған пайдаланушы тіркелгісін қолданады. [API тест сценарийлері](../../tests/test_documents_api.py) · [Тест фикстурасы](../../tests/conftest.py)

| Сценарий | Күтілетін нәтиже |
| --- | --- |
| Құжаттар жоқ кезде тізімді сұрау | `GET /documents` HTTP `200` кодымен бос тізімді қайтарады. |
| Құжатты жасау және қайта оқу | `POST` HTTP `201` кодымен тіркеу нөмірін қайтарады. Жаңа құжатты ID арқылы оқуға болады. |
| Жарамсыз тақырып | Бір таңбадан тұратын тақырыппен жіберілген `POST` сұрауы HTTP `422` алады. |
| Мәртебесі бойынша сүзу | Сұралған мәртебедегі құжаттар ғана қайтарылады. |
| Белгісіз идентификатор | `GET`, `PATCH` және `DELETE` сұраулары HTTP `404` алады. |
| Ішінара жаңарту және жою | `PATCH` тақырыпты өзгертеді және басымдық мәнін сақтайды. `DELETE` HTTP `204` қайтарады. Одан кейін сол құжатты оқу сұрауы HTTP `404` алады. |
| Арнайы таңбалар арқылы іздеу | API жолды сүзгінің мәні ретінде өңдеп, дұрыс тізімді қайтарады. |

Репозиторийдің түбірлік бумасында виртуалды ортаны белсендіріп, мына командаларды орындаңыз.

```bash
python -m pip install -r requirements.txt
python -m pytest -q tests/test_documents_api.py
```

Осы тест тобын жергілікті ортада іске қосу нәтижесі — `7 passed`.

Код сапасын көрсету үшін SQLModel модельдеріндегі өріс ұзындығы мен дерек түріне қойылған шектеулерді, жоқ нысанды сұрағандағы HTTP `404` жауабын және параметрлерді байланыстыру арқылы SQLAlchemy өрнектерінен іздеу шарттары қалай құрылатынын түсіндіріңіз. [Модельдер](../../app/database/models.py) · [API маршруттары](../../app/routers/documents.py)

2. Репозиторийдің түбірінен `docker compose down`, содан кейін `docker compose up --build -d` командаларын орындаңыз. Сервистердің дайындығын `docker compose ps` арқылы тексеріңіз. [Docker арқылы іске қосу](../06/README.md)

4. Swagger UI бетінде `GET /documents` жауабын және белгісіз ID бойынша сұрау жібергенде алынатын HTTP `404` кодын көрсетіңіз. [Swagger UI](http://localhost:8000/docs)

## Бақылау сұрақтары

- **Автоматтандырылған тестілер не үшін қажет?** Олар әр өзгерістен кейін API-ді бірдей қадамдармен тексереді. Қолмен көрсету сценарийді пайдаланушы тұрғысынан бағалауға көмектеседі. Тестілер жауап күйін, мазмұнын және дерекқордағы өзгерістерді жүйелі түрде тексереді.
- **`TestClient` не істейді?** Ол тест процесінің ішінде қолданбаға HTTP сұрауларын жеткізеді. Тексеру сол процесте орындалатындықтан, Uvicorn серверін бөлек іске қосудың қажеті жоқ.
- **Тест клиентіне HTTP кітапханасы не үшін керек?** Ол HTTP сұрауын құрып, күй кодын, тақырыптарды және JSON мазмұнын тексеруге болатын жауап береді. `httpx` кітапханасында `async`/`await` негізіндегі тестілерге арналған асинхронды клиент те бар.
- **Жасанды интеллект кодты шолуға қалай көмектеседі?** Ол шеткі жағдайларды ұсынады және кіріс деректерін тексеру, қателерді өңдеу әрі дерекқормен жұмыс істеу бөліктерінде нені қарау керегін көрсетеді. Ұсыныстар кодты талдау және тестілерді қайта орындау арқылы расталады.
- **Регрессиялық тест деген не?** Ол бұрыннан күтілетін әрекеттің кейінгі өзгерістерден соң да сақталуын тексереді. Мысалы, `PATCH` маршруты жаңартылған кезде тест тақырыпты өзгерту құжаттың басымдық мәніне әсер етпейтінін тексереді.
